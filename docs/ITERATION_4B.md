# 4B execution status: core plus world lifecycle, not yet playable

Branch: iteration-4-main-4a. Package 1 commit 85dbe8c adds the isolated execution state machine and ten tests; its CI passed according to the user. This step 4B.2a connects it to CombatWorld with execute(), executionAvailable(), executionTargetReady(), owned execution snapshots, event records and twelve world tests. New CI is pending. Main is unchanged.

Still NOT connected: R/input API, real hero/enemy execution choreography, halo rendering, blood/stains, sparks/embers, actual camera zoom/shake, visual toggles or new browser/native execution scenarios. They are the remaining 4B.2 render/input work. Do not call this package a ready execution preview. Existing character animations and the HTML actors are not copied.

World contract: start requires playing hero with lamp, no dash/action/sweep/hit reaction, weak living target nearby, facing and unobstructed line. Only the single existing enemy is supported. Target AI and root positions are held from entry, not merely from piercing; no automatic staging/root movement is introduced here. Other enemies are not added or simulated by this patch. The target stops attacking during the whole capture; manual/external damage still reduces the hero lamp and does not cancel unless lethal. Future multi-enemy integration must keep non-target AI active.

Attacks, sparks, dash and repeated execute reject while captured, with no hidden queue. Extraction once sets target HP=0, dead mode and charred flag, and restores lamp capped at 100. Victory waits until finished, so the blade recovery may complete. On hero death, cancelled execution and target state freeze until restart; no later extraction or revival. If target identity changes or an unextracted target dies externally, cancel without reward; if the current single enemy is dead the world may enter victory. Restart clears both current and previous state, events and corpse flags.

Draft tuning remains: <=30% max enemy life, reach 1.4, cone 120 degrees, reward 30, duration 10.8s. Existing attack damage/reach, dash and aim controls remain. Particle event rendering must use simulation events/seeds, never random render sampling. Snapshot presentation interpolation changes elapsed only; logical flags stay at current simulation state. Pause remains caller-controlled by not stepping the world.

Approved visual sequence to implement next: fiery halo; pin with blade embedded in enemy and ground; free right hand; enemy struggles around a fixed pin; left-hand lamp extracts fire and chars body; regrip then pull blade with legs/corpse constraints, return behind hero. Blood on impact/pierce, embers during drain/extraction, sparks on pull, bounded optional camera zoom/shake. Geometry near walls, true rig grip/limb lengths, foot contacts and death pose need actual render tests and manual review. Existing camera follow only is retained in 4B.2a; presentation helpers are not an actual camera implementation.

Full CI, browser/native execution checks and human acceptance are not replaced by unit tests. 3C.4 acceptance remains open. No main merge is authorized.
