# 4B execution: package 1, isolated state machine

Branch: iteration-4-main-4a. Main is not changed. This package adds execution.ts and ten contract tests. It does NOT yet bind R, CombatWorld, the hero/enemy renderer, particles or the actual camera. No ready playable execution is claimed.

Approved sequence: overhead fiery halo on a weakened enemy; pin enemy with the large one-handed blade embedded through the body into the ground; release right hand; enemy struggles without moving the pinned point; offer left-hand lamp; extract fire and char body; regrip before pulling blade out; return sword behind hero. Blood at impact/piercing, sparks/embers during burning and blade extraction, controlled camera approach and impact shakes must be integrated in package 2, not copied from the HTML stand-in renderer.

Explicit draft tuning pending gameplay acceptance: weakened means living enemy at <=30% max HP; reach 1.4 cells; facing cone 120 degrees; lamp restoration 30 capped at 100; 10.8s full cycle. These are configurable preview defaults, NOT silently established final balance. Existing maximum enemy HP is to be supplied by the adapter.

Core invariants: scalar owned snapshots; target/heading locked at entry; ordinary damage does not interrupt; death cancels before extraction when processed first; extraction event once per state; dead hero cannot receive restored lamp; coarse steps preserve event order; presentation sampling is pure. Pause is implemented by the caller NOT advancing the state. Restart must discard execution state and its event/particle history. Camera presentation is time-based and bounded, not a real camera integration.

Integration obligations: enforce attack/sweep/dash/input exclusions, no queued actions after execution, validate target identity/range/obstacles on entry, prevent execution target AI motion while pinned, keep other enemies active, apply extraction once and never after death, defer victory until choreography completes, record charred corpse, keep blade fixed while hand is free, emit effects from simulation events with seeded RNG, collision-check staging/root motion and fit target pose near obstacles. Decide recovery of surviving pinned enemy and weapon state if hero dies or the target becomes invalid. Do not claim these are already implemented.

Render obligations: use actual hero rig and feet/limb constraints, not procedural HTML actors; halo must reflect weak-target eligibility; camera and all effect timing must freeze on pause; expose camera/shake toggles without changing gameplay; preserve existing 4A/4C regressions. Full build/typecheck/unit/browser/native Windows CI and human visual acceptance remain required. This source package has not yet run those checks. No merge into main is authorized.
