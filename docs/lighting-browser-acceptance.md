# Nine-source browser acceptance candidate

The workflow retains the established spawn-to-first-brazier browser regression and adds a separate Chromium acceptance script for nine source variants. Each variant starts in a fresh run with all sources off. A test-only placement puts the hero at a nearby collision-free location with a validated route to that model so the target is inside the camera. This is not claimed as nine browser routes from the normal spawn; the separate original-brazier regression still covers spawn navigation, and unit tests cover routes for all placements.

Target candidates are obtained from actual geometry and checked for occlusion, then selected with the Playwright mouse. Canvas focus is set before hover and the live target must remain selected for 250 ms. Only physical KeyF requests the action. No direct ignition, resource payment or target setter is used. The enemy is moved away in the browser fixture to isolate interactions.

For every model the script records before, contact and lit canvas frames; measures the actual rendered hero lamp against the bound contact point on the contact plateau; verifies exactly one six-LAMP payment, the expected model emitter count, one lit instance, and no extra payment from repeated F. Additional cases cover six-LAMP rejection without approach, seven-LAMP ignition leaving one, manual approach cancellation, Escape pause cancellation, damage reducing funds before contact, a door action with all nine models present and reset. Restart restores all nine sources and removes their emitted lights.

Reports include actor/controller state, payment events, hover attempts, contact measurements and observed CI frame timing summaries. These summaries are not hardware performance guarantees or a performance acceptance threshold. Reports and failure screenshots are retained and printed by CI on both operating systems. The script intentionally fails on missing visibility, missed contact captures or a gameplay mismatch rather than bypassing the check.

Publication does not establish a passing run. Unit and browser results remain to be observed. Human visual review of posture, attachment, ASCII readability and occlusion is still required; screenshots alone are not approval. Reduced-motion coverage, exhaustive freeze/blur/death scenarios, full performance profiling, all-door browser permutations and final level-design acceptance are not claimed by this patch. No gameplay implementation or main merge is included.
