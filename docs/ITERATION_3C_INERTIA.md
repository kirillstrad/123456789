# Iteration 3C.3 - bounded body and equipment inertia

One block adds eight scalar response channels plus velocities to MotionState. They advance in finishMotion from actual speed changes and visual angular velocity, using an exact critically damped constant-target update with amplitude/velocity bounds. Body, sword, lamp, cloth and chains have different response rates. Channels decay when unforced, reset on death/createMotion, and are interpolated as snapshot-owned scalar values. Rendering does not advance them. Old snapshots without inertia fields retain a bounded legacy-load fallback.

Existing locomotion offsets now read those channels rather than adding a second layer. Small sword/hand and lamp offsets remain visual only. Leg targets are preserved by the original IK. Existing combat crossfades and combatSecondary gating protect active attack/sweep poses. No movement constants, action timings, damage, combo rules, lamp-life brightness, room, HUD or hero assets are changed. Caller-owned secondary state is not simulated or reset by this block.

Ten new tests cover bounds/rates, time partitioning, settling, invalid dt/death, interpolation, world start-stop-reset, gameplay independence, authored active rigs, real limb lengths and render determinism. Tests are prepared, not locally executed. The next commit must pass the full CI and publish updated previews before visual acceptance. Pause behavior relies on the existing pause handler not advancing CombatWorld; repeated sampling alone cannot evolve inertia.

Limits: scalar animation responses, not a free physical weapon, cloth mesh, individual chain simulation or whole-body balance solver. Winning hides added load and lets state decay through existing terminal ticks; retry resets it. Timing constants and small pose coefficients are initial tuning values requiring user-machine visual review. Performance, antivirus scanning and publisher signing are still separate unfinished stabilization tasks. Main is not a write target.
