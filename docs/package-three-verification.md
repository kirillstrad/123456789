# Combined verification candidate

The implementation and node-fixture migration for all three packages are now accompanied by a branch CI workflow and a new browser acceptance script. Publishing this commit starts the first combined Ubuntu/Windows run. No passing result is known yet. Do not merge before inspecting results and evidence.

The acceptance script uses real keyboard E/F/R and WASD, ordinary occlusion-aware pointer sampling, controlled browser time, the production state API and production renderer. All 21 E sources reject normal F requests and ignite only after the E release; all eight manual sources reject E and use one six-LAMP payment. Manual contact keeps the existing 0.04 error threshold. Six doors are exercised from both sides, followed by physical passage. There is one physical aisle journey from the unchanged spawn into the expanded room; individual variant cases use test-only actor placement and an enemy parked away from the test. No direct ignition, HP injection or resource-payment setter is used. Damage and three real strike requests are used for bounded budget/execution fixtures.

Other cases cover repeated E/F, six/seven-LAMP budgets, manual/pause approach cancellation, insufficient funds before contact, E pause/nonlethal damage/held movement, visible cool hint pixels at one LAMP versus full lantern light, hero-backdrop activity, faint-flash expiry, reset and runtime errors. A real Canvas compositor test checks partial occlusion and front/back order using synthetic rectangles; this is not a claim that all full-room wall/painter-order cases are visually certified. Screenshots and JSON are retained on failure and success. Reduced-motion mode is used for deterministic captures; motion behavior also has node contract coverage but still requires human review.

The new source-policy browser scenario supersedes the old branch-specific nine-F-target scripts for this branch. They are not silently used against incompatible rows. The full npm test suite and existing portable boot/combat/export and pause/input browser regressions remain required. CI uses the normal source build, not a spoofed main/demo preparation identity. Browser diagnostics still run after a successful build when node tests fail, without suppressing the failed job result. Native Windows packaging, hardware FPS guarantees and human visual acceptance are not included. Main is unchanged.
