# Last Service iteration 4 — verification candidate

This patch does not assert that the prologue has passed acceptance. The connected tools cannot run a checkout with npm/Playwright here; neither TypeScript nor Playwright is installed in the isolated Node environment. New CI executes the actual repository build and browser checks after the approved push. It has read-only repository permission, uploads artifacts, and never commits generated files or modifies main.

Reproduced on the prior route: optional spawn may be requested inside the hero; a new roster may be requested while an existing enemy touches the hero, which CombatWorld rejects; command-time execution and ritual observations can be missed by the host's post-step event-time filter; a dead hero can advance a completed encounter. The route now defers unsafe dynamic placement, observes successful persistent execution/ritual effects, and ignores dead actors. The radius ceiling is conservative and checked against real bestiary definitions by the compiled-core verifier. Static collision/spawn validation remains the verifier's responsibility.

Portable packaging now selects the reachable dependency graph, checks generated syntax with Node VM, rejects missing/external/dynamic require dependencies, escapes embedded script terminators, and checks the HTML entry contract. Browser smoke now waits for the actual dialogue, not only a tutorial queued behind an animation; reports and screenshot are refreshed on failure as well as success.

After build, verify-last-service-runtime.mjs uses actual compiled CombatWorld, geometry, door, ritual, and finale/loadout helpers. It checks spawn geometry, door opening, grid reachability, a real light hit, restoration and full-lamp handling, arena confinement, both scripted boss endings and carried lamp. Boss HP/position are arranged for the ending checks; this is not a full natural combat playthrough or a balance test. Arena visual/environment rendering is still covered only indirectly; manual/full-route browser acceptance remains pending.

Commands: npm run build:prologue; npm test; node tools/verify-last-service-runtime.mjs; node tools/browser-check-last-service.mjs; npm run test:browser. Inspect docs/last-service-verification.json in the CI artifact and its exact testedSourceCommit. A passed automated report always keeps humanVisualAcceptance=false. Existing menu integration, room checkpoints, art/animation polish, persistent saves and actual human approval are not added here.

Local preparation: four new regression cases fail against the previous route implementation; the corrected route plus portable-packager suite passes all 13 tests. Syntax checks pass for seven JS/test/tool files, and workflow YAML parses. The compiled-core and Playwright checks have not run in this environment.
