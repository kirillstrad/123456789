# Iteration 3C - combat entry and secondary-load block

Combined patch: capture actual rendered foot endpoints when an action begins; store them in simulation snapshots; bridge feet into authored light/heavy, sweep and hit poses over the first .12 normalized clip progress; suppress locomotion-derived secondary offsets as authored combat poses take over. Existing recovery crossfades remain; this patch does not replace the combat action machine.

Capture uses the real locomotion/transition rig, current world contacts and any preceding entry bridge. Queuing input does not restart entry. Automatic combo starts capture the previous fixed-step pose and bind to the new action id. Ordinary locomotion contacts are still disabled during combat. Entry correction is legs-only, uses original IK and cross-body bounds, and is fully absent at progress .12 and later. Sword/lamp endpoints, active arm poses, attack timings, damage, queue/cancel rules and movement speed are not modified.

Entry data is deep-copied into snapshots and cleared on action changes, completion/cancel, death, victory and reset. No renderer-owned clock or mutable global pose cache is introduced. Without a loaded hero module, headless worlds omit visual entry data. Secondary load gating changes only added locomotion-derived cloth/chain offsets; caller-provided base secondary state is preserved. This is not a new physical spring system or a completed redesign of all body/weapon inertia.

Ten new tests cover idle/walking attack entry, unchanged active rigs, sweep/hit entry, queue/combo identity, movement cancel and support recovery, terminal/reset cleanup, snapshot ownership, sword/lamp endpoints, secondary-load suppression and sampling determinism. They are prepared, not locally executed. Run the full CI and inspect its playable artifacts before visual acceptance.

Known limits: large aim changes may invoke cross-body or reach bounds rather than preserve an unreachable foot; no dedicated turn-step or whole-body balance animation is added. Combo capture uses the previous simulation tick, not an event-time resimulation. Existing end-of-action transitions need human review, including short inputs, repeated combos, pause/resume and collisions. Full iteration acceptance, user-hardware performance testing, antivirus checks and publisher signing are not completed by this patch. Work is confined to iteration-3c-stabilization; main is not changed.
