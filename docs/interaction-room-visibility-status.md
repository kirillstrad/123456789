# Combined patch: package 3 visual implementation candidate

Branch: iteration-5j-interaction-room-visibility. Main is unchanged. Packages 1 and 2 are implementation candidates, not verified releases. CI stays deferred until package 3 fixture migration and final verification setup are complete. This intermediate commit uses [skip ci].

Package 3 visual work now selects three scarlet fragments on deformed existing cloth edges: upper shoulder seam, waist seam and lower hanging panel. Materials retain matte cloth; warm skin shades receive a modest desaturation while hand/forearm gains remain. Sword and chain base colors are cooler and muted; one sword fragment and a sparse subset of chain cross-links receive cool highlights. Added line fragments follow the same rig transform and dash visibility as the hero. No new point light, outline shell or combat geometry is added.

Background contrast is connected after world lighting and before ASCII painting in the actual game renderer. It uses the existing foreground-occluded hero mask, never an unoccluded full-body silhouette. Hero cells and image alpha are not changed. Only neighboring non-hero cells within two ASCII cells are darkened, by at most 13 percent with falloff. Fully hidden heroes produce no effect. Foreground pixels immediately adjacent to an exposed hero fragment can also be affected because this is a 2D visible-mask operation, not depth-aware relighting. Final halo/occlusion/readability and performance acceptance is pending. Fire hints are composited afterward and retain their independent brightness.

Tests for appearance and backdrop are updated but NOT run. Still required before the shared CI: migrate old room-dependent unit and browser fixtures, validate new native contact points and door routes, add physical E/F and hint-occlusion browser coverage, enable final branch verification, then inspect failures and visual evidence. Package 3 and the combined patch are not complete yet. No merge into main is requested.
