# ASH / IRON — ITERATION 1.0.1

Стабильное имя сборки: ASH_IRON_ITERATION_1_0_1. Это полный самостоятельный проект первой итерации, не патч. Временная рабочая папка предыдущего ответа была восстановлена из закреплённого героя и исходников; эта версия заново типизирована, собрана и проверена в браузере.

## Быстрый запуск

1. Распакуйте весь ZIP в отдельную папку.
2. Запустите START.bat. При установленном Node.js будет открыт локальный сервер 127.0.0.1:5173 (или следующий свободный порт до 5183). Окно держать открытым, Ctrl+C останавливает сервер.
3. Если Node.js нет, батник откроет готовый CONTROL.html. Его можно открыть двойным щелчком напрямую.

Для запуска готовой игры не нужны интернет, npm install, Python или CDN. Сначала распаковать ZIP, не запускать файлы внутри просмотрщика архива. Для разработки рекомендуется Node.js 20.19+.

## Согласованные границы первой итерации

Включено: текущий герой NAVE 196, одна изометрическая комната, пол/стены/колонны/гробницы/клетки/свечи, дыхание и ходьба, WASD/стрелки, столкновения, пауза, сброс контрольного кадра, единый LAMP 100, PNG и JSON-диагностика. Фиксированный шаг симуляции 60 Гц, цель вывода 30 FPS, интерполяция положения.

Не включено: бой, AI противников, серии ударов, казнь, рывок пеплом, урон, лечение, прогресс, новые комнаты, новое меню или огненный фон. В исходном vendor/hero.js сохранены все прежние клипы, но игровая сцена вызывает только breath и walk. Никакого доступа к способностям через игровые клавиши в этой версии нет.

## Управление

WASD / стрелки — движение. ЛКМ не перемещает героя. Space — пауза/продолжение. FREEZE FRAME / RESUME — то же мышью. RESET CONTROL FRAME — начальные позиция и камера. SAVE FRAME PNG — снимок кадра. SAVE REPORT — JSON с параметрами, таймингами и buildId. PERFORMANCE — метрики без F2.

Исправление фокуса: после Resume, Reset и смены рендера фокус возвращается на игровой canvas. WASD не блокируется просто потому, что до этого была нажата кнопка. Нажатия в select/input не перехватываются игрой.

## Визуальный профиль

Размер canvas 1008×864, игровая область 1008×720, ASCII 196×140, zoom 65, сила лампы 160, радиус 120, окружение 125, чёрный 100. Плотность и масштаб не понижаются автоматически.

Текущий герой — точный hero.js из kirillstrad/123456789, коммит ce7f8bc0dbf2ef420fdcda4c3f8b76f14943b5fa. Git blob героя d7b64e103433a1763f33fd42fc7286f51dd14eb0 проверяется тестом. Геометрия и дизайн героя не менялись.

REFERENCE сохраняет исходные lighting() и glyph() присланного HTML. Это CPU-режим для контроля изображения, он может быть медленнее.

WEBGL2 — трёхпроходный вывод: освещение, площадное усреднение до 196×140, атлас символов. Это не выбор самой яркой точки ячейки. Нативное сглаживание Canvas и выборка атласа отличаются, поэтому визуальное совпадение следует оценить вручную. Оба режима сохраняют мир, героя, позицию и профиль. При отсутствии WebGL2 применяется REFERENCE.

Нельзя выдавать CPU submit за GPU time. В отчёте GPU time=null, отдельного замера GPU пока нет. На устройстве пользователя FPS этой сборки не измерены.

## Разработка и повторная сборка

Исходники TypeScript расположены в src/. Vite настроен через vite.config.ts. Геометрия окружения и исходные функции эталонного рендера оставлены в двух изолированных JS-модулях с TypeScript-описаниями, чтобы миграция не изменила визуал. Герой сохранён в public/vendor/hero.js побайтово.

`npm install` — первоначальная установка инструментов разработки, нужен интернет.
`npm run dev` — Vite.
`npm run typecheck` — строгая проверка TypeScript.
`npm run compile` — компиляция исходников в runtime и копирование ассетов.
`npm test` — пересборка runtime и тесты.
`npm run build` — проверка типов, runtime, Vite-сборка и автономный HTML.

BUILD.bat и TEST.bat выполняют эти действия. CHECK_READY_BUILD.bat / `node --test` проверяют уже вложенный runtime без установки инструментов. Для готового запуска START.bat инструментальная установка не нужна.

CONTROL.html и dist/CONTROL.html — автономный результат сборщика tools/portable.mjs. runtime/ — скомпилированный модульный проект для server.mjs. Корневой index.html относится к Vite-разработке; для file:// использовать CONTROL.html.

## Повторное обращение к сборке

Сохраняйте весь ZIP и не заменяйте файлы частями из других версий. В отчёте всегда присутствует buildId ASH_IRON_ITERATION_1_0_1. Для следующей итерации можно передать этот ZIP или разместить его содержимое в репозитории, сохранив структуру папок. Автоматических изменений GitHub не выполнено.

MANIFEST.json содержит SHA-256 файлов и позволяет проверить, что исходники и готовый runtime относятся к одной сборке. Не редактируйте runtime вручную: меняйте src/, затем пересобирайте. Исходный visual-reference.html в reference/ предназначен для сравнения, это не точка входа новой сборки.
